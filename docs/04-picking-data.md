# 功能4：拣货数据参考值

## 概述

上传 **发票** + **系统导出拣货数据**，匹配箱规历史数据库，生成 **内部拣货数据参考值**。

## 输入文件

| 文件 | 必填 | 说明 |
|------|------|------|
| 发票 `.xlsx` | ✅ | 可多选合并；含货箱编号/品名/重量尺寸 |
| 系统导出拣货数据 `.xlsx` | ✅ | 运单号 + 扩展箱号对照 |
| 报价文件 `.xlsx` | ✅ | 按「报价来源」解析，必传；不再回退服务器默认报价表 |
| 箱规历史数据库 `.xlsx` | 可选 | 不传用服务器默认 `拣货数据/箱规历史数据库.xlsx` |

报价来源（`quotation_source`）三选一，对应 `price_mode`：

| 来源 | price_mode | 说明 |
|------|-----------|------|
| 报价单 | `quotation_first` | 按仓库取 应收单价/应付单价/供应商渠道；报价表无价时回退每周报价表 |
| JTT每周渠道报价表 | `weekly_first` | 按 渠道+仓点+计费重 匹配应收单价（输出 G 列），匹配不到回退报价单 |
| 导出报价表模版 | `export_template` | 按 **SO号=运单号** 直取 服务/仓库代码/应收运费单价/成本运费单价/供应商服务 |

**报价来源以文件本身为准（自动识别，`detect_quotation_file_type`）：** 若上传的报价文件
有「运单号」表头且带「应收运费单价」或「成本运费单价」，一律判定为导出报价表模版并
强制走 `export_template`，忽略下拉框的选择。**为什么必须这样：** 下拉框默认是「报价单」，
一旦误选，模版会被 `parse_quotation` 当报价单解析——它的「应收运费单价」碰巧被识别成
应收单价（**输出 G 列看起来是对的**），而「成本运费单价/供应商服务」取不到（输出 H/I 全空）、
仓库代码为空的行（海外仓如 `PENG-P134`）直接丢失，SO号 直取与收件人兜底一行都不走。
结果是「半对半不对」，极易被误判成「差一点点没匹配上」。反向也做了守卫：选了
「导出报价表模版」但文件没有「运单号」表头时，控制台告警并整表标红（不猜）。

## 匹配逻辑

> **列号约定**：下面写的列号是**写入期列号**（`VAT号` 列插入之前）。2026-09-21 起输出文件在
> 「客户渠道」后插入 `D=VAT号`，所以**输出文件里 D 及以后整体右移一位**：
> 国家 E、仓库代码 F、应收/应付/供应商渠道 G/H/I、FBA ID L、箱数 O、长/宽/高 Q/R/S、
> 参考长/宽/高 Y/Z/AA、计费重 AF，标红范围 A–I。最终列序：`A 下单时间 | B 系统SO号 |
> C 客户渠道 | D VAT号 | E 国家 | F 仓库代码 | G 应收单价 | H 应付单价 | I 供应商渠道 | …`

1. **SO 号匹配**：发票货箱编号 → 前 12 位 FBA ID → 匹配系统扩展箱号 → 取运单号(SO)
2. **客户渠道(C列)**：报价来源=导出报价表模版时取模版「服务」；否则报价表 JTT 渠道 → 发票「服务」列
3. **仓库代码(E列)**：取发票「收件人姓名」（地址信息）；导出报价表模版命中时以模版
   「仓库代码」为准（该列为空时回退模版「收件人」，并按 `clean_template_warehouse`
   清洗：仅当 `-` 后是 Amazon 才取 `-` 前，`TCY2-Amazon`→`TCY2`，
   `PENG-P134`→`PENG-P134`）
4. **箱规匹配**：品名 + 重量/尺寸 → 箱规历史数据库 → 取标准箱规（写入期 V/W/X/Y → 输出 W/X/Y/Z）
5. **VAT号(D列，2026-09-21 新增)**：**每张发票各自识别**，取该发票「VAT号」表头单元格右侧
   那一格的值（天图/TR 赛诺吉：表头 `E10 = VAT号*`，值 `F10`——`F10:G10` 是合并格；航乐：表头 A7，值 B7），
   在 1–25 行 × 1–12 列范围内找表头（忽略 `*`/空白/冒号），再从右邻 1–3 列取第一个非空值，
   清洗为 `DE123456789` 这类 **DE 开头**的号。**识别不到/发票没填 → 留空**，不猜测、
   不回退其它发票的值；多发票模式下每张发票的行各自带自己的 VAT号。
6. **报价填充**：
   - 报价单 → 按仓库代码取应收单价/应付单价/供应商渠道
   - 每周报价表 → 按 渠道+仓点+计费重 覆盖 E 列（输出 F 列）
   - 导出报价表模版 → 收尾 pass 按 SO号 覆盖 仓库/应收/应付/供应商服务（模版价权威，
     不被前面的报价逻辑覆盖）
7. **无历史匹配**：V/W/X/Y 留空并标红
8. **报价模版未覆盖**：
   - **取不到 SO号时按收件人兜底并回填 SO号**：海外仓/快递派单的箱号前缀常与
     拣货导出的「扩展箱号」对不上（`OWS260909001` 单号 vs `IBR5768…` 长号），
     `so_no` 为空 → 按 SO 直取整行落空。这类行用发票侧收件人（仓点）反查模版：
     先 `(仓点, 渠道)` 精确匹配，再退化为只按仓点；发票侧带 `-Amazon` 后缀时
     用清洗后的值。命中后**把模版行的运单号回填成 B 列系统SO号**——
     下游 `gen_bill.py` 的参考值解析是**按 SO号 分组且带向下填充**（`cur_so`），
     B 列为空的海外仓行会被静默并入上一行的 SO（SO/渠道/仓库三项全错），
     若空 SO 行排在首行则整行被丢弃。故回填 SO 是必须项，不是美化。
     控制台打印 `↩️ 收件人兜底命中：…→SO xxx，应收yyy`
   - **两道守卫**：① 同一键下模版存在多个不同价 → 拒绝兜底（避免张冠李戴）；
     ② 命中的运单号已被别的行按 SO 取走 → 拒绝兜底并提示
     `⚠️ 运单号已被其他行占用，放弃兜底：…`
   - 兜底仍落空 → C/F/G/H 留空（输出 C/G/H/I），该组 A–H 标红（输出 A–I），控制台汇总
     `⚠️ 报价模版未覆盖：…`（E 列保留发票侧回退值，便于人工定位）

> 客户渠道同时用于：计费重「快递派」最低计费重规则、JTT每周渠道报价表的渠道匹配。
> 模版服务名含「快递派」时，计费重列自动用 `=ROUND(MAX(参考实重:总实重, 箱数*12),0)`
> （输出期 `=ROUND(MAX(AD{r}:AE{r},O{r}*12),0)`；写入期即 `AC:AD` / `N`，
> 插入 VAT号 后由 `_shift_formula_cols(f, 1)` 整体右移一位）。

**插入 VAT号 列的技术要点**：openpyxl 的 `insert_cols(4)` 只搬移值与样式，**不翻译公式、
不搬合并区域、不重映射列宽**，因此三件事都手工做——① 数据区合并先 `unmerge_cells`；
② 列宽按旧下标 `idx>=4 → idx+1` 快照后删除旧键再回填（否则宽度仍挂在旧字母上）；
③ 写入期生成的公式统一 `_shift_formula_cols(f, 1)`；④ 标红行的 D 列补红底（新列不继承）。

## 箱数计算

货箱编号 `U{start}-{end}` 格式：`箱数 = end - start + 1`

## 输出

文件名：`内部拣货数据参考值_{日期}_{N}箱.xlsx`  
模板自动填充公式列（材积重/周长差异/总实重/计费重等）

输出列序（2026-09-21 起）：

```
A 下单时间 | B 系统SO号 | C 客户渠道 | D VAT号 | E 国家 | F 仓库代码 |
G 应收单价 | H 应付单价 | I 供应商渠道 | … | L FBA ID | O 总箱数 |
P 实重 | Q/R/S 长/宽/高 | X 参考实重 | Y/Z/AA 参考长/宽/高 | AF 计费重
```

## 命令行

```bash
cd 拣货数据
python3 export_picking_data.py <发票.xlsx> <系统导出.xlsx> [输出.xlsx] [导出报价表模版.xlsx] [报价方式]
```

- 页面：`GET /picking`
- 提交：`POST /picking_export`（字段：`picking_invoice[]`, `picking_system`,
  `quotation_source`(`quotation`/`weekly`/`export_template`), `picking_quotation`(必传),
  `picking_history`(可选)）
