# 功能1：TR账单自动生成

## 概述

上传 **一份**「内部拣货数据参考值 `.xlsx`」（由 `/picking` 拣货数据模块生成），自动生成拓锐 FBA 分段开票账单。

## 输入文件

| 文件 | 说明 |
|------|------|
| 内部拣货数据参考值 `.xlsx` | 拣货模块输出；账单所有字段均直接取自本表**同名列** |

> 按**表头名**取列（`_norm_header`/`_find_col`），列号变动不影响解析：拣货模块 2026-09-21 起在「客户渠道」后新增 `D=VAT号`，参考值整体右移一位，账单侧无需改动，也不取 VAT号 列。

## 核心规则（2026-09-21 改：与参考值严格一一对应）

账单行 = 参考值表**从上到下的行序**，逐行一一映射；**不按 SO 归并、不重排**，也不做任何推断/回退匹配。

| 账单列 | 取自参考值列 |
|--------|--------------|
| A 发货日期 | 下单时间（格式 `M月D日`，解析不了留空） |
| B SO | 系统SO号 |
| C FBA | FBA ID |
| D 走货渠道 | 客户渠道 |
| E 仓库代码 | 仓库代码 |
| F 箱数 | 总箱数(CTN) |
| G/H/I 长宽高 | **参考长 / 参考宽 / 参考高**（参考尺寸，非发票实际尺寸） |
| J 计费重 | 计费重列数值；该列为公式且无缓存值时按模版公式复刻 `ROUND(MAX(参考实重×箱数, 参考材积重×箱数))` |
| K 应收单价 | **应收单价列原值**；为空即留空，不回退仓库/前缀匹配 |

- **组头列合并单元格规则（2026-09-21 新增）**：`下单时间 / 客户渠道 / 国家 / 仓库代码` 若为**合并单元格**，合并区间覆盖的**每一行取区间左上角同一个值**，确认后（日志打印 `🧩 合并单元格：N 段…`）再进入后续字段匹配。openpyxl 读合并区域时只有左上角有值、其余行是 `None`，逐行读会让「仓库代码」在跨组合并时被清空（账单 E 列空白、报价表A 少一条）；现在按区间取值，非合并列仍保持「组首行给值、组内继承」的旧行为
- **计费重为 0 的行会被丢弃**（报关费按行收取，留 0 行会凭空多算报关费），丢弃行号打印在日志里，便于与参考值表核对行数
- **S列(报关费)** = 350/1.06，**每一行**都收；T = S×0.06
- **汇总公式**：L=`K*0.07/1.06`、M=`K*0.35`、N=`K*0.58`；O=`L*J`、P=`O*0.06`、Q=`M*J`、R=`N*J`；AA=`SUM(O:Y)`
- **合计行（2026-09-21 新增 U/V/W/X/Y 求和）**：`sum_cols = F/J/O/P/Q/R/S/T/U/V/W/X/Y/AA`，逐列 `=SUM(x{首行}:x{末行})`，与模板自带合计行口径一致
- **sheet1 B2（国际货物运输代理服务 金额，2026-09-21 新增 V/X/Y）**：
  `='{第2个sheet名}'!Q{合计行}+R{合计行}+U{合计行}+W{合计行}+V{合计行}+X{合计行}+Y{合计行}`
  = 国际运费1(Q) + 国际运费2(R) + 清关费(U) + 附加费(W) + **税金(V)** + **其他费用(X)** + **退税损失(Y)**
  （明细表表头 L3 行标签为 `O 国内运费 / P 国内税点6% / Q 国际运费1 / R 国际运费2 / S 报关费 / T 报关税费6% / U 清关费 / V 税金 / W 附加费 / X 其他费用 / Y 退税损失 / AA 总应收(RMB)`；
  合计行行号**动态取**，不是写死的 23）
- **报价表A（2026-09-21 扩充为五元组去重）**：按 `(月份, 周, 客户渠道, 仓库代码, 应收单价)` 去重陈列——
  ① 同渠道+同仓点若单价不同 → 各列一条；② 五元组**完全一样**的重复行只保留**唯一一行**，不重复生成一摸一样的多行。
  比较时按归一化键：单价 `13` / `'13 '` / `13.0` 视为同一条（`_price_key`），渠道/仓库忽略所有空白（`_text_key`）
  （解析期先按 `(客户渠道, 仓库代码, 应收单价)` 粗去重，写入期再按五元组终去重）
- **标题**：`至：广州拓锐科技有限公司（M.D-M.D）` 按参考值「下单时间」最早日期所在周（周一~周日）

## 输出文件名（2026-06 修复）

**动态月份**，不再硬编码「5月」：

```
{year}年{file_month}月拓锐FBA仓-分段开票账单-JTT({date_range_str}) RMB {total}.xlsx
```

| 字段 | 规则 |
|------|------|
| `year` | 发货周区间周一所在年份 |
| `file_month` | `date_range_str` 第一个 `.` 前的数字（发货周区间起始月） |
| `date_range_str` | 按订单**下单时间/创建日期**所在周（周一~周日），如 `6.16-6.22` |
| `total` | 应收合计，四舍五入到 1 位小数 |

示例：`2026年6月拓锐FBA仓-分段开票账单-JTT(6.16-6.22) RMB 12345.6.xlsx`

日期列不限定格式：Excel 日期或文本 `2026-08-21`（含 `2026/08/21`、`8月21日`、尾部空白）均会解析；下单时间/创建日期为空回退发货日期→工作日期；均无则 `file_month` 回退到当前月。

## Web 下载（中文文件名）

- 后端：`send_file(..., download_name=output_name)` 直接传 UTF-8 中文名
- 前端 fetch 解析 `Content-Disposition`：**优先** `filename*=UTF-8''...`，再回退 `filename=`
- Railway 环境依赖 Werkzeug `download_name`，不要手动拼 `filename*` header

## 命令行

```bash
cd "TR账单自动生成"
python3 gen_bill.py <内部拣货数据参考值.xlsx> [输出.xlsx]
```

## Web 接口

- 页面：`GET /bill`
- 提交：`POST /generate`（字段：`ref_file`，单个「内部拣货数据参考值」）
