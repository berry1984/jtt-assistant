# 功能3：发票转换 TR→天图/航乐/美琦/英美/凯鑫

## 概述

将 TR/思锐/赛诺吉 客户下单发票转换为目标供应商模板。

## 支持格式

| 源 | 目标 |
|----|------|
| TR/思锐/赛诺吉发票 | 天图下单发票 |
| 同上 | 航乐-英国发票 |
| 同上 | 航乐-欧洲发票 |
| 同上 | 美琦美线发票 |
| 同上 | 英美-美国空海运发票（下单模版） |
| 同上 | 英美-欧洲/英国/加拿大发票（下单模版） |
| 同上 | 凯鑫发票（英欧加/美线通用） |

## 订单列表匹配规则（美琦 / 天图 / 航乐 / 英美 / 凯鑫）

- 所有目标均可另传**订单列表** excel（含「运单号」「仓库代码」「供应商服务」列）。
- 匹配优先级：
  1. **订单号匹配**：源「客户订单号」== 订单列表「运单号」
  2. **仓库代码匹配**：源「地址库编码」（为空取源「收件人姓名」，如 IND9/POZ1/RFD2）== 订单列表「仓库代码」
- 命中的行提供两个字段回填：
  - **运单号** → 回填客户订单号（各目标落点：**美琦** B1；**天图** B14；**英美** B14；**凯鑫** B14；**航乐** 输出文件名中的订单号）
  - **供应商服务** → 回填目标发票的**服务/渠道**（**渠道抓取**：**美琦** B3 服务；**天图** B1 服务；**英美** B1 服务；**凯鑫** B1 服务（不在 `服务名称` 下拉清单则自动追加）；**航乐** I7 渠道）
- 未上传订单列表 / 未命中 / 订单列表无「供应商服务」列时：客户订单号保留源值，服务保留源「服务」字段。
- CLI：`python3 convert_invoice.py <发票.xlsx> --to <目标> --order-list <订单列表.xlsx>`

## 美琦转换要点

- 模板：`美琦美线发票模版.xlsx`（3 sheet：`发票`/`亚马逊仓库代码`/`服务渠道`）
- 头部 Row 1-17（A=标签/B=值），数据列头 Row 18（A-R），数据行 Row 19 起
- **收件人信息**按「地址库编码」从 `亚马逊仓库代码` sheet 查表（联系人/地址一/城市/省洲/邮编/国家），查不到回退源字段原值
- 地址库编码 = 源「地址库编码」，为空取源「收件人姓名」（仓库代码，如 IND9）
- 客户订单号（B1）= 源「客户订单号」；若上传订单列表，按对应订单号查表回填为**运单号**；客户参考号（B2）= 源「客户参考号」或客户订单号；电话/邮箱/公司名称留空
- 服务（B3）= 订单列表对应订单号的**供应商服务**（渠道抓取），未命中回退源「服务」；不在「服务渠道」下拉清单时自动追加
- 报关方式归一化（美线）：含「退税」→ 一般贸易，含「代理」→ 代理报关
- **海关编码（J 列）保持源原值、不改单元格格式、不加小数点**（如 `9405429000` 原样输出）
- 货箱编号（A 列）= 运行式箱号区间（如 1-3）
- **产品图片（O 列）**：从源发票提取、以 twoCellAnchor 嵌入（参考天图方案）；模板自带表头图（Row≤17）保留，示例数据图丢弃
- **PO Number（P 列）** = 源 V 列（行级优先，其次头部 PO Number）
- **物品箱号（Q 列）** = 单行总箱数
- **物品 FBA ID（R 列）** = 货箱编号中 `U00000` 前的 12 个字符（如 `FBA19CW3W9W7U000001-3` → `FBA19CW3W9W7`）

## 源文件要求

- Sheet 名 `Page1`
- Row 1-16/28 头部，Row 18+ 数据行
- 含货箱编号、品名、申报单价/数量、重量尺寸、产品图片

## 天图转换要点

- B3-B13 收件人信息直填客户原值，不做 VLOOKUP
- B1 服务 = 订单列表对应订单号的**供应商服务**（渠道抓取），未命中回退源「服务」；并确保追加到 Sheet2 服务下拉
- B14 客户订单号 = 源「客户订单号」；若上传订单列表，按对应订单号回填为运单号
- 产品单箱申报总价 = 单价 × 数量（计算值，非复制）

## 英美转换要点（2026-09-29）

一份转换函数 `convert_to_yingmei(tr, out, region='us'|'eu', order_list_path, expected_station)` 覆盖两个目标：

| 目标 | 模板 | 主 sheet |
|---|---|---|
| 英美-美国 | `英美-美国空海运发票模版9.15更新.xlsx` | `模板`（辅助 sheet：`渠道列表`/`亚马逊地址库`/`站点`） |
| 英美-英欧加 | `英美-欧洲英国加拿大发票模板9.8更新.xlsx` | `模板`（辅助 sheet：`渠道列表`/`地址库`/`站点`） |

**这两份是「下单模版」而不是发票**：没有运单号、没有总价/合计块、没有开票日期。表头是 A 列标签 / B 列值的网格（1–24 行），明细表头在第 **25** 行、数据从第 **26** 行起。结构上天图式（`A1`=`服务*`，A 列打头为货箱编号）。

- **表头每格显式写入（含空串）**，像天图那样直接覆盖模板自带的 VLOOKUP：收件人/公司/地址一~三/城市/省州/邮编/电话/邮箱一律取源值，**不保留查表公式**。
- **B2 地址库编码** = 源「地址库编码」，TR 发票无此列（恒空）→ 实际落源「收件人姓名」（仓库代码，如 `RFD2`/`POZ1`）。
- **B14 客户订单号** = 源「客户订单号」；上传订单列表时按对应订单号回填为运单号。
- **B15/B16 带电/带磁** = `是`/`否`（注意本模版词表是 是/否，**不是**天图的 `带电/不带电`）。
- **B17 报关方式** 归一化到模版下拉词表 `买单报关/报关退税/合并报关`（含「退税」→`报关退税`，含「买单」→`买单报关`，含「合并」→`合并报关`，空→`报关退税`）。⚠️ **不要复用美琦的规则**（`退税→一般贸易`、`代理→代理报关`）——那两个值不在本模版下拉里。TR 语料目前只出现过 `报关退税`。
- **B18 清关方式**：源发票有值则透传；TR 恒空 → 保留模板自带默认。
- **申报币种** 按目的国自动填：`US/USA/CA/CAN`→`USD`，`GB/UK/GBR`→`GBP`，其余欧洲国家代码→`EUR`；未识别回退源「申报币种」。
- **所在货站** 来自网页站点输入框 / CLI `--station`（复用现有 `expected_station` 机制），**不做目的国/渠道自动推断**。两套模版共用同一份 20 个站点清单（EU 版 `站点` sheet 的 A1 是表头 `站点`，不算选项）。
- **行偏移（唯一分支之处）**：EU 比 US 多一行 `B20 EORI*`，因此 EU 的 申报币种→B21 / 所在货站→B22 / 备注→B23 / 箱数→B24；US 则是 币种 B20 / 货站 B21 / 包退运 B22 / 备注 B23 / 箱数 B24。
- **明细 A 列货箱编号 = 源箱号原值**（如 `FBA19F2WRL3HU000001-4`），不重编号、不逐箱展开。
- **辅助 sheet（`渠道列表`/`亚马逊地址库`/`地址库`/`站点`）全部保留**——它们喂 B1/所在货站的 DV 下拉，删掉会破坏引用。US `渠道列表` 读 **A 列**（无表头），EU 读 **B 列**（B1 是表头 `渠道名称`）。
- **不做图片嵌入**：两份模版 `xl/media` 全空、无 drawing，S 列就是文本的产品图片链接列，因此不需要 `_embed_images_as_cell_images`，也不设行高（与天图 M 列 / 航乐 W 列的嵌入方案不同）。
- **留空字段**：W 承运商 / X 跟踪号（源无此信息）；EU 额外的 Y 产品尺寸* / Z 产地 同样留空，不臆造。

## 凯鑫转换要点（2026-09-29）

- 模板：`发票转换/凯鑫-发票模版更新20260924.xlsx`
- 结构：主 sheet `发票`（A 列标签 / B 列值的表头网格 **Row 1–26**，明细表头 **Row 27**，数据 **Row 28 起、A–S 列**）；
  辅助 sheet `FBA地址库编码表`（564 行地址库，含欧洲 / GB 英国 / CA 加拿大 / US 美国 四段）与 `服务名称`（462 行渠道下拉）。
  **一张模版覆盖英国/欧洲/加拿大/美国**，没有英美那样的区域分支。
- **收件人信息 B2–B13 剥掉模版自带的 VLOOKUP，改由 Python 查 `FBA地址库编码表` 写死**：
  模版原文是精确 `VLOOKUP(B2, FBA地址库编码表!A:D, 4, 0)`，而源发票只给仓码（`POZ1`/`WRO5`），
  表里却是带渠道后缀的编码（`POZ1-02977`/`POZ1-62080`/`WRO5-02977`/`WRO5-59225`）→ 直接放源值会满屏 `#N/A`。
  匹配优先级：**地址编码精确 → FBA仓库代码 → 地址简称 → 地址编码包含（len≥3）**；
  第 2–4 步命中多行时**用 TR「收件人国家代码」消歧**（`POZ1`/`WRO5` 在 DE 与 PL 各有一行），消不了歧取表中第一行；全部未命中回退源字段。
  解析出的单元格一律是**字面值，全表公式数 = 0**。
- **B2 写的是源仓码原值**（`POZ1`），不是消歧后的表格编码（`POZ1-02977`）——B3–B13 已是写死的解析值，B2 不再驱动任何公式。
- **B24 申报币种归一到模版的中文词表 `美元/英镑/欧元`**（⚠️ 不是英美模版的 ISO 代码 `USD/GBP/EUR`）：
  源值含 USD/美金/美元→美元，GBP→英镑，EUR→欧元；源值认不出（TR 该字段常空）按目的国推断
  （US/CA/MX→美元、GB/UK→英镑、其余欧洲→欧元）。
- **B17 报关方式只映射两个词**：含「退税」→`报关退税`，含「买单」→`买单报关`，其余原值。
  ⚠️ 本模版 DV 里**没有「合并报关」**（说明正文提到，但不在下拉中）；也**不要复用美琦的** `退税→一般贸易` / `代理→代理报关`。
- **B15/B16 带电/带磁** = `是`/`否`（同英美）。**B18 交税方式**原样透传（DV 词表 `包税/自主税号/自税递延`，TR 实测 `包税` 已在内）。
- **必填列空值补 `/`**：明细里标了 `*` 的列（Q 产品SKU、S 产品ASIN 这类源发票本就常空）源值为空时写 `/`，不留空。
  唯一例外：**M 产品型号**模版未标 `*` → 允许留空。
- **明细 A 列 = 源箱号原值**（含 `-5` 箱数后缀），一行一个源产品行；因此**行数 ≤ B26 箱数**，与模版样例的逐箱格式不同。
- **产品图片从源发票提取、嵌入 P 列**（单元格写 `[图片]`，无图写 `/`），复用 `_embed_images_as_cell_images`。
  模版自带的两张图都在 **P 列（P27 表头样例图 / P28 样例数据图）**，**两张都是样例**→ `ws._images = []` 全清
  （与美琦"保留表头图"不同）。
- **样例残留清理**：模板 Row 28/29 有两条样例数据（`FBA15LC3MHP9U000001`/`HAJ1` 等），写入前按 A–S 清空，
  并**摘掉 O28/O29 的样例超链接**——⚠️ 模版把链接挂在 `cell.hyperlink` 上（载入时 `ws._hyperlinks` 为空），
  只清 `value` 不够，openpyxl 保存时会把 `hyperlink.target` 回填成单元格内容，输出里就会冒出 `amazon.co.uk` 样例 URL 并带外链。
- **行样式**：模版只把 Row 27/28/29 格式化到 `微软雅黑 9` + 居中 + 行高 37，Row 30 起是未格式化的 `宋体 11`，
  所以行号超出模版已格式化范围时**逐格从 Row 28 复制 font/border/fill/alignment** 并显式设行高 37（仿英美 `_item_cell`）。
- **无「所在货站/预计交货站点」字段**：网页不显示站点输入框、CLI 不接 `--station`。
- 辅助 sheet `FBA地址库编码表` / `服务名称` **必须保留**——`服务名称` 喂 B1 的 DV 下拉（读 **B 列**，B1 是表头文字，扫描从 row 2 起）。

## 尺寸导出规则（2026-09-24）

**所有目标格式（天图 / 航乐-UK / 航乐-EU / 美琦 / 英美-美国 / 英美-英欧加 / 凯鑫）导出的长宽高，均在客户原始长宽高上整体向下调整**，
统一走 `convert_invoice.py::_apply_dim_rule()`：

| 客户原值小数尾数 | 处理 | 示例 |
|---|---|---|
| > 0.5 | 抹去小数点后的数据 | 45.6 → 45 |
| ≤ 0.5（含整数） | 整数位 −1 | 45.5 → 44、45.0 → 44、48 → 47 |

> ⚠️ **整数同样 −1**（尾数 0 属于「≤ 0.5」）：`48 → 47`。
> 旧规则（2026-08-29 ~ 09-24）「第一位小数 >5 舍小数，否则 −0.5」（45.5 → 44.5）已废弃。

- 空值 / 非数字 → 天图、美琦、凯鑫原样留空；航乐按 0 处理
- **航乐材重（S 列）、CBM（T 列）及其合计按调整后的尺寸计算**，与 P/Q/R 自洽：
  `S = P×Q×R ÷ 6000(欧)/5000(英)`，`T = P×Q×R ÷ 1000000`；仅三维均 > 0 时计算
- 写入位置：天图 P/Q/R、航乐 P/Q/R(+S/T)、美琦 G/H/I、**英美 D/E/F**、**凯鑫 G/H/I**
  （英美重量在 C 列、凯鑫重量在 F 列；两份模版都无材重/CBM 列，不需跟随重算）

## 产品图片（2026-06 修复）

**问题**：转换后图片不显示 / 尺寸过大。

**方案**：`_embed_images_as_cell_images()` 写入标准 Excel 绘图（非 IMAGE() 公式为主）：

| 组件 | 说明 |
|------|------|
| `xl/media/image_N.png` | 图片二进制 |
| `xl/drawings/drawing1.xml` | **twoCellAnchor**，图片跟随单元格大小 |
| worksheet `<drawing>` | 关联 drawing rels |

**源图提取**（`TRInvoice`）：
- 标准 Excel 嵌入图（openpyxl `_images`）
- WPS `cellimages.xml` + DISPIMG 公式（`_extract_wps_cell_images`）

**列位置**：天图 → M 列；航乐 → W 列。数据行行高设为 80。

Web 版 `app.py` 仍可将图片提取到 `/temp_images/`，但本地/CLI 转换以 twoCellAnchor 嵌入为准，打开 xlsx 即可见图。

验证工具：`python3 发票转换/check_format.py <输出.xlsx>`

## 命令行

```bash
cd 发票转换
python3 convert_invoice.py <源发票.xlsx> <输出.xlsx> \
    [--to 天图|航乐-uk|航乐-eu|美琦|英美-美国|英美-英欧加|凯鑫] \
    [--order-list <订单列表.xlsx>] [--station <所在货站>]

# 批量：把目录下所有源发票按同一目标转换（批量模式不支持 --station，所在货站留空）
python3 convert_invoice.py --batch --in-dir ./发票 --out-dir ./输出 --to 英美-美国
python3 convert_invoice.py --batch --in-dir ./发票 --out-dir ./输出 --to 凯鑫
```

## Web 接口

- 页面：`GET /invoice`
- 提交：`POST /invoice_convert`（字段：`invoice_file`, `target`, `order_list`（可选）, `expected_station`（可选，美琦与英美目标用；凯鑫不用））
- 独立小应用（`发票转换/app.py`，走 `POST /convert`）只接受 `invoice_file` + `target`。
